# Nextended.CodeGen

📚 **[Vollständige API-Referenz](/de/projects/codegen-api)** — jeder öffentliche Typ und Member, erzeugt aus der kompilierten Assembly.

🇬🇧 [This page in English](/projects/codegen)

Roslyn-Source-Generator — DTOs und Interfaces aus Ihren Entities, stark typisierte Klassen aus JSON/XML, Lookup-Tabellen aus Excel und Dokumentation aus Quelldateien.

Das Mapping zwischen Entity und DTO wird wahlweise als Extension-Methoden (`ToDto()`/`ToEntity()`) oder als partieller
[Mapperly](https://mapperly.riok.app/)-Mapper generiert (`[AutoGenerateDto(MappingStrategy = DtoMappingStrategy.Mapperly)]`
oder `DefaultMappingSettings.Strategy` in der Konfiguration). Methoden, die Sie im eigenen Teil der partiellen Mapper-Klasse
deklarieren, überschreiben die generierten. Mapperly braucht die Dateien auf der Platte, also `OutputPath` und
`MappingOutputPath` setzen und `Riok.Mapperly` referenzieren.

## Fluent-Konfiguration (empfohlen)

**Der empfohlene Weg, die Generatoren zu konfigurieren.** Statt Attributen an den Entities und einer `codegen.json` beschreiben eine
oder mehrere Konfigurationsklassen, was generiert wird — wie ein `ResponseFilter<T>` oder ein FluentValidation-Validator. Attribute und
`codegen.json` funktionieren unverändert weiter; die Fluent-Konfiguration verfeinert sie, und mit ihr wird `codegen.json` optional.

```csharp
using Nextended.Core.CodeGen;
using Nextended.Core.Enums;

// die DTOs einer Entity
public sealed class ProductDtoConfig : DtoConfig<Product>
{
    public ProductDtoConfig()
    {
        Ignore(x => x.InternalNote);
        Property(x => x.Sku).PropertyName("ArticleNumber");
        MappingStrategy(DtoMappingStrategy.Mapperly);

        // ein zweites DTO derselben Entity (eine View)
        View("ProductRow", v => v
            .Ignore(x => x.Category, x => x.Tags)
            .BaseMembersFirst()
            .Order(x => x.Name, x => x.Price)
            .ToDtoMethodName("ToRow"));
    }
}

// das ganze Projekt: was in der codegen.json stünde, die zu generierenden Typen, Regeln für Gruppen von Typen
public sealed class AppCodeGen : CodeGenConfig
{
    public AppCodeGen()
    {
        Defaults(d => d.Namespace("MyApp.Contracts").OutputPath("./Generated/Dtos/").InitializeCollections());
        Dto<Entity>(e => e.Ignore(x => x.TenantId));          // erreicht jedes DTO und jede View jeder Entity
        Dto<Category>();                                       // ohne [AutoGenerateDto]
        Dto(typeof(Page<>), p => p.Suffix("Model"));           // offene generische Typen über typeof
        IgnoreType<LegacyImport>();
        ForNamespace("MyApp.Domain.Codes", n => n.Namespace("MyApp.Contracts.Codes"));
        ForAssembly("MyApp.Admin", a => a.Defaults(d => d.Namespace("MyApp.Admin.Contracts")));
    }
}
```

| | |
| --- | --- |
| Gefunden | automatisch: jede Klasse im Projekt, die von `CodeGenConfig` oder `DtoConfig<T>` erbt (beliebiger Namespace, auch `partial`) |
| Gelesen, nicht ausgeführt | der Generator analysiert den Konstruktor: erlaubt sind Aufrufe der `Nextended.Core.CodeGen`-API, Konstanten (auch `const`, `nameof`, Enum-Werte, konstante Interpolationen), `typeof`, Member-Selektoren `x => x.Member` und verschachtelte Lambdas. Alles andere (Variablen, berechnete Werte, `if`, Schleifen, `x => x.A.B`) ist ein Fehler `NCG020` an genau dieser Stelle — nie still ignoriert |
| Namen | jede Einstellung heißt **genau wie die Attribut- bzw. json-Eigenschaft**, die sie spiegelt (`Namespace`, `Suffix`, `PreClassString`, `PropertyName`, `InitializeCollections`, ...); `bool`-Einstellungen nehmen ein optionales `true` |
| Zusätzlich | `Ignore`/`Include` (hebt `[IgnoreOnGeneration]` und `PropertiesToIgnore` auf), `Property`, `View`, `Order`, `BaseMembersFirst`, `Emit` (Datei pro DTO aus einer Vorlage mit `{Dto}`, `{DtoNamespace}`, `{Source}`, ...), `ExcelGeneration`, `StructureGeneration` |
| Vorrang | `codegen.json` → Fluent-`Defaults` (bleiben Defaults) → Attribute → `ForNamespace` → `Dto<T>`/`DtoConfig<T>`. Mehrere Klassen werden nach vollem Typnamen zusammengeführt; widersprüchliche Werte melden `NCG022` |
| Member-Regeln | gelten für das Standard-DTO und die Views des Typs und für die DTOs abgeleiteter Typen (Suche: View → Typ → Basistypen → Namespace-Regeln). Eine Regel am abgeleiteten Typ für einen geerbten Member wirkt nur in dessen Views (`NCG023`) |
| Ohne `codegen.json` | relative Pfade beziehen sich auf das Projektverzeichnis |
| Diagnosen | `NCG020` nicht lesbar · `NCG021` unbekannter Member · `NCG022` Konflikt zwischen Klassen · `NCG023` Regel ohne Wirkung aufs Standard-DTO · `NCG024` `Emit` nicht schreibbar · `NCG025` Typ kann kein DTO haben · `NCG026` Aufruf unbekannt (Nextended.CodeGen aktualisieren) |

Voraussetzung: ein Nextended.Core mit `Nextended.Core.CodeGen` und ein Nextended.CodeGen, der es liest. Ausführlich mit allen Tabellen auf der
[englischen Referenz](/projects/codegen#fluent-configuration); lauffähig im
[CodeGenFluentSample](https://github.com/fgilde/Nextended/tree/main/Tests/TestProjects/CodeGenFluentSample) (kein Attribut, keine json);
Entwurf und Begründung: [Fluent configuration — design](/projects/codegen-fluent-design).

## DTO-Einstellungen im Überblick

Alle mit Beispielen auf der [englischen Referenz](/projects/codegen#generic-types). Ohne Angabe bleibt die Ausgabe wie bisher.

| Einstellung | Wo | Wirkung |
| --- | --- | --- |
| `KeepEnumFlagsAndUnderlyingType` | `DtoGeneration` | generierte Enums behalten `[Flags]` und den zugrunde liegenden Typ (`: short`) |
| `KeepAttributesOnGeneratedClass`, `PreClassString` | `[AutoGenerateDto]` eines Enums | Attribute des Quell-Enums bzw. Text über dem Enum (z. B. ein `JsonConverter`) |
| `KeepPropertyAttributesOnGeneratedClass`, `PreClassString` einer Property | Attribut | wirken auf alle Member der Klasse, auch skalare und Enum-Member |
| `InitializeCollections` | `DtoGeneration` | nicht-nullbare Collection-Properties starten mit `[]` |
| `TypesToIgnore` | `DtoGeneration` | Typen (und über `AutoGenerateDerived` erfasste abgeleitete Typen) ohne DTO |
| `SkipReverseMapping` | `DefaultMappingSettings` | nur Quelle → DTO, kein `AssignTo`/`ToNet` zurück |
| `MapDerivedTypes` | `DefaultMappingSettings` | Mapperly: Member eines Basistyps werden auf das DTO des Laufzeittyps gemappt (`MapDerivedType`) |

## DTO-Views: mehrere DTOs einer Entity

Das erste `[AutoGenerateDto]` eines Typs beschreibt sein **Standard-DTO**. Jedes weitere `[AutoGenerateDto]` am selben Typ erzeugt ein
weiteres DTO, eine **View**: eine andere Form für einen anderen Client (alte API, Listenzeile, Export) mit eigenem Mapping. Ein Typ mit
nur einem Attribut erzeugt genau das, was er bisher erzeugt hat.

```csharp
[AutoGenerateDto(AutoGenerateDerived = true)]                       // Standard: QuotationDto
[AutoGenerateDto(GeneratedClassName = "QuotationAbp",               // View: QuotationAbpDto
    PropertyNames = ["DateCreatedUtc=CreationTime", "DateUpdatedUtc=LastModificationTime"],
    UseViews = ["PortAbp", "HubCode", "QuotationStatusAbp"])]
public class Quotation : GuidBaseEntity { /* ... */ }

// eine View für alle Code-Entities: einmal an der gemeinsamen Basisklasse
[AutoGenerateDto(AutoGenerateDerived = true)]
[AutoGenerateDto(GeneratedClassName = "HubCode", PropertiesToIgnore = ["DateCreatedUtc", "DateUpdatedUtc"])]
public abstract class CodeEntity : GuidBaseEntity { /* ... */ }

var abp = quotation.ToQuotationAbpDto();   // das Standard-DTO bleibt quotation.ToDto()
```

| | |
| --- | --- |
| `GeneratedClassName` | Pflicht für eine View, zugleich ihr Schlüssel für `UseViews` und `GenerationPropertySetting.View` |
| Member | alle öffentlichen Properties inklusive geerbter (flach, kein Basis-DTO), minus eigenes `PropertiesToIgnore`; auch bei abstraktem Typ eine konkrete Klasse |
| `PropertyNames` | `"Quelle=Ziel"`-Paare, benennen Member dieses DTOs um, auch geerbte; gewinnt gegen `GenerationPropertySetting.PropertyName` |
| `UseViews` | Member, deren Typ (oder dessen Basistyp) eine der genannten Views deklariert, bekommen diese View statt des Standard-DTOs (auch in Collections und an Standard-DTOs) |
| `OutputPath` | eigener Ausgabepfad für die Datei dieses DTOs |
| `[GenerationPropertySetting(View = "...")]` | mehrfach erlaubt; eine Einstellung für eine View ersetzt dort die ohne `View` |
| Mapping | je View eigenes Mapping: `To<ViewKlasse>()` (oder `ToDtoMethodName`), Extensions oder Mapperly (`<ViewKlasse>Mapper`); eine View eines abstrakten Typs bzw. eines Basistyps mappt nur in Richtung View |
| Gemeinsame View | mehrere Entities teilen eine View über eine gemeinsame Basisklasse; gleichnamige Views unabhängiger Entities werden gemeldet (`NCG011`) und weggelassen |
| Diagnosen | `NCG010` View ohne Namen, `NCG011`/`NCG012` Name bzw. Mapping-Methode vergeben, `NCG013` unbekannte View in `UseViews`, `NCG014` ungültiger `PropertyNames`-Eintrag |

Die neuen Einstellungen liest der Generator per Name, er braucht also keine bestimmte Nextended.Core-Version; das eigene Projekt braucht
eine Nextended.Core-Version, die sie deklariert. Ausführlich mit erzeugtem Code:
[DTO views (englisch)](/projects/codegen#dto-views-several-dtos-of-one-entity).

Generische Typen: ein Typ mit generiertem DTO wird auch als Typargument ersetzt, in Membern, Basisklassen und Constraints
(`HolderDto<AddressDto>`, `where TUnit : UnitDto`). Ist ein Typparameter auf einen Typ mit DTO eingeschränkt, bekommen die
Mapping-Methoden einen zweiten Typparameter für die DTO-Seite (`AssignTo<TUnit, TUnitDto>`).
